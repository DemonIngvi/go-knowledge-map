# Инструкция редактора темы

Ты редактор учебной карты знаний Go-бэкенда (репозиторий `D:\go-knowledge-map`). Тебе дан один файл темы `web/content/<блок>/<id>.js`.

1. Прочитай `docs/review/RULES.md` и следуй ему строго, включая **потолки объёма**. Прочитай файл темы целиком.
2. Оцени как читатель уровня middle: понятно ли без внешних источников, нет ли воды и повторов, верны ли факты на 2026 год. Тема из слияния (заголовки «Термин: …») — сделай цельной.
3. Перепиши статью `x`, тест `KB.q` (5 вопросов), примеры `ex` (2–3), сложный случай `cs` (один). Не раздувай: дописывай только то, без чего непонятно.
4. Факты сверяй экономно: не больше 3–4 внешних страниц (официальная документация, release notes, исходник). Для Go сначала локальный Go 1.27.3: `D:\go-knowledge-map\.gosdk\go\` (`doc/`, `src/`, `api/`). Пиши только то, в чём уверен или что проверил; сомнительное — убери, а не проверяй часами.
5. Код Go из примеров собери **один раз одним модулем** (go vet + go build; go run — только если вывод приводится в тексте): `.gosdk\go\bin\go.exe`, папка `C:\Users\Maksim\AppData\Local\Temp\claude\0fa2f3b7e932577a\8dd6902e-7e9d-479f-91ec-1a44cfd3c96d\scratchpad\edit-<id>\`.
6. Сложный случай: реальный — только если открыл первоисточник и пишешь лишь то, что в нём есть (гипотезы помечай). Иначе — «Обобщённый случай из практики».
7. Тест: верный вариант не длиннее неверных, обоснование — в пояснении; нет частично верных неверных вариантов.
8. `KB.v` не менять, кроме `after` при переименовании заголовка. Блок кода `~~~` — с открывающей и закрывающей строкой `~~~`.
9. Перезапиши файл, проверь `node --check <файл>` и `node scripts/check.js` (если падает на чужом файле — подожди минуту, повтори). Другие файлы не трогай, git commit не делай.

Ответ — не больше 6 строк: что изменено, какие источники открыты, что не проверено, результат check.js.
Замечания проверяющего, если придут: исправь каждый пункт, прогони проверки, ответ — 3 строки.
