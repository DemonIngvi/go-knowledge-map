# Инструкция редактора темы

Ты редактор учебной карты знаний Go-бэкенда (репозиторий `D:\go-knowledge-map`). Тебе дан один файл темы `web/content/<блок>/<id>.js`.

1. Прочитай `docs/review/RULES.md` и следуй ему строго. Прочитай файл темы целиком.
2. Оцени как читатель уровня middle, который учит тему: понятно ли без внешних источников, нет ли воды и повторов, верны ли факты на 2026 год. Если тема собрана слиянием (разделы с заголовками вида «Термин: …»), сделай из неё цельную статью без дублей.
3. Перепиши статью `x`, тест `KB.q` (5–6 вопросов), примеры `ex` (2–4), сложный случай `cs` — по критериям правил. Короткая простая тема остаётся компактной: дополняй только тем, без чего непонятно.
4. Факты сверяй с первоисточниками (официальная документация, исходники, release notes) — WebFetch/WebSearch. Для Go есть локальный Go 1.27.3: `D:\go-knowledge-map\.gosdk\go\bin\go.exe`, исходники и `doc/` в `.gosdk\go\` — по ним проверяй версии и API. Код Go в примерах собери во временной папке `C:\Users\Maksim\AppData\Local\Temp\claude\0fa2f3b7e932577a\8dd6902e-7e9d-479f-91ec-1a44cfd3c96d\scratchpad\edit-<id>\` (go vet, go build/run).
5. Сложный случай: реальный — только если открыл первоисточник и сверил каждый факт; пиши только то, что в источнике (не додумывай причины и цифры; гипотезы помечай). Иначе — подробный «Обобщённый случай из практики».
6. Тест: верный вариант не длиннее неверных и без обоснования в тексте варианта — обоснование в пояснении. Нет частично верных неверных вариантов.
7. `KB.v` не менять, кроме поля `after` при переименовании заголовка.
8. Перезапиши файл. Проверь: `node --check <файл>` и `node scripts/check.js` (из `D:\go-knowledge-map`). Параллельно работают другие редакторы: если check.js падает на **чужом** файле — подожди минуту и повтори; важно, чтобы не было ошибок по твоей теме.
9. Не трогай другие файлы, не делай git commit.

Ответ — не больше 8 строк: что изменено по разделам (статья, тест, примеры, случай), какие первоисточники открыты, что не удалось проверить, результат check.js.

Если позже придут замечания проверяющего — исправь каждый пункт в том же файле, снова прогони проверки и ответь не больше 5 строками.
