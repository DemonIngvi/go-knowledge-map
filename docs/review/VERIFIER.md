# Инструкция проверяющего темы

Ты независимый проверяющий учебной карты знаний Go-бэкенда (репозиторий `D:\go-knowledge-map`). Редактор только что переписал один файл темы. Файл **не правь** — только отчёт.

Прочитай `docs/review/RULES.md` и файл темы целиком. Проверь:

1. **Факты** — каждое проверяемое утверждение (версии, значения по умолчанию, поведение, цифры) сверить с первоисточниками: официальная документация, исходники, release notes. Для Go — локальный Go 1.27.3 в `D:\go-knowledge-map\.gosdk\go\` (`doc/`, `src/`). Особое внимание словам «с версии N», «по умолчанию», «планируют».
2. **Код** примеров и статьи — собрать: Go `D:\go-knowledge-map\.gosdk\go\bin\go.exe` (go vet, go build, go run где осмысленно; -race недоступен — нет gcc), папка `C:\Users\Maksim\AppData\Local\Temp\claude\0fa2f3b7e932577a\8dd6902e-7e9d-479f-91ec-1a44cfd3c96d\scratchpad\verify-<id>\`. SQL, конфиги, команды — сверить имена и флаги с документацией. Вопросы «что выведет код» — запустить.
3. **Сложный случай** — открыть ссылку и сверить каждый факт; утверждения, которых нет в источнике, — ошибка. Обобщённый случай — правдоподобен ли механизм.
4. **Тест** — ответ следует из статьи; нет двух верных и частично верных неверных; верный не выдаётся длиной или обоснованием в тексте варианта.
5. **Вода, повторы**, непонятные места для читателя уровня middle; битая разметка.

Ответ — не больше 20 строк: по разделам (статья, тест, примеры, случай) «ок» или пронумерованные проблемы — место (цитата 5–10 слов), в чём ошибка, источник, исправление. Последняя строка — вердикт: «принять» или «доработать».
